# Recorder upload recovery

Status: implemented and tested locally; deployment and installed app verification are pending.

The native fallback uploads the computer, microphone, and mixed tracks in 8 MiB parts after capture stops. A checkpoint beside each sealed file stores its storage upload ID and file size before any bytes are sent. A retry or app restart lists completed storage parts and sends only missing or incorrectly sized parts. If a successful completion response was lost, the completed object is recognized without sending the file again. Only the interrupted part needs retransmission.

Every server request authenticates the paired device and checks the recording intent's owner, active workspace, meeting management access, and state. The destination is sealed before issuing URLs. Storage object identities derive from the authorized intent, client recording, and track; callers cannot supply arbitrary storage keys. Completion checks the part numbers, sizes, and storage ETags before finalizing the object. Existing recording completion still performs registration and transcription dispatch.

The native fallback records AAC in M4A containers directly, using mono 48 kHz audio and a 64 kbps constrained variable bitrate target. The nominal size is about 29 MB per hour per track, or 86 MB for the computer, microphone, and mixed tracks together, plus screenshots and container overhead. Actual bitrate varies with content. Mixing retains the separate source tracks. Old queued WAV files remain supported.

Microphone capture enables Apple's voice processing for noise suppression and echo cancellation. Automatic gain control is disabled to avoid raising quiet background sounds, and other audio ducking is set to its minimum. The selected input device is reapplied after enabling processing. If microphone startup fails with voice processing, the recorder releases that engine and retries once with a fresh engine without noise suppression, preserving the selected input. If the retry fails, recording still reports an error. SDK metering does not enable a competing voice processor. Physical microphone tests are still required to evaluate typing noise, quiet speech, and interaction with meeting playback. This configuration is a conservative native default, not a benchmark proving superiority over every noise suppression model.

Desktop SDK upload requests omit the original server request URL from provider metadata. Behind a reverse proxy that URL can be `http://0.0.0.0:8080`; Recall rejects localhost URLs anywhere in the payload, even when the actual realtime callback is public. Keep `RECALL_REALTIME_WEBHOOK_URL` configured to the public callback endpoint.

SDK discovery matches the scheduled meeting URL when available, and otherwise requires exactly one detected meeting. The start command is not proof of capture: the sidecar waits for the matching `recording-started` event and forwards its `rawMedia` flag. The pinned SDK is 2.0.43. Local SDK capture is reported as lacking background shared content capture. Settings → Background meeting capture provides explicit Google Meet and Zoom setup actions. These request automation before a call and show the SDK permission result; they do not request automation during startup or recording. Google Meet setup uses the supported default browser. App access alone does not prove Raw Media availability: workspace enablement and a live `recording-started.rawMedia` result are still required. In a live Google Meet test with Raw Media enabled, the development recorder uploaded both shared slides while Chrome displayed another tab.

If SDK capture fails, the app explains the failure and offers **Choose a window**. This explicit fallback lists the visible windows of other apps on a page inside the recorder panel and captures the chosen one. It does not use the macOS content-sharing picker: after the Recall helper has run and exited in the same app process, replayd stops delivering that picker's result, which left the start waiting forever. Waiting for a choice can be cancelled from the page or the summary, and Quit or Restart cancels it instead of being refused; a cancelled start fails its intent like any failed start. Screenshots require an identifiable window. Audio can continue when screenshots are unavailable. It saves an initial JPEG, then checks every five seconds for meaningful changes. Browser windows require an identifiable active document URL, and changes to the captured window identity pause screenshots while audio continues. Images have a maximum long edge of 1600 pixels and JPEG quality 0.75. Screenshots use the recoverable upload path with recording relative timestamps translated to the meeting timeline.


Uploads begin after capture stops. This change does not change the Recall SDK's own upload lifecycle. Meeting SDK capture and native fallback remain separate paths.

Deploy the server route before distributing the updated desktop app. The existing prepare and complete routes remain available to older apps. No database migration or new credentials are required.

R2 expires incomplete multipart sessions after seven days by default. Check the actual bucket lifecycle policy before release. If a session has expired, the app starts a new one using the retained local recording. Do not delete local files while uploads remain pending. Abandoned sessions, including a start response lost before its upload ID can be saved, are cleaned up by the storage lifecycle policy.

Local verification includes actual AAC encoding and mixing at both 48 kHz and 44.1 kHz input, duration preservation, screenshot change detection and timestamps, compressed audio and image completion, server recovery, incomplete completion rejection, scope and request validation, paired device authorization, and native recovery from a persisted session. Before release, interrupt a real upload after several parts, restart the app, reconnect, and verify that transferred bytes resume at the missing part. Also interrupt the completion response, verify one recording registration, and play the resulting audio. Automated tests do not establish live storage or installed app behavior.

The AAC conversion test reproduces a sample loss bug in the previous one shot converter: 48 kHz stereo input became 8.53 seconds instead of ten. Same rate channel conversion now uses the synchronous PCM conversion API. Resampling explicitly drains its input and uses the expected output capacity. The regression runs through the production writer and synthesizer without recording a microphone.

Before release, also verify the macOS window picker, screenshots after a slide change, minimized and closed windows, browser tab changes, and a real microphone with typing during quiet and normal speech. Confirm the meeting's playback volume remains usable with voice processing active. Build and synthetic audio checks do not prove these physical capture paths.
